## 0. 한 줄 요약

현행 홈은 "게임 사이트로 안 읽히고 무분별한 나열"이다. **릴리즈노트를 괴리의 프레임으로 쓰는 홈**으로 바꾸고,
아이콘 스케일을 올리고, 라인 축을 넣고, 팔레트를 **LoL 브랜드 색(V4 협곡 나이트)** 으로 교체한다.
멀티게임 확장은 `[data-game]` 속성 하나로 중립 램프를 스왑하는 구조로 이미 설계돼 있다.

## 1. 절대 깨면 안 되는 것

1. **첫 화면은 "괴리"로 읽혀야 한다.** 패치노트를 위에, 통계를 아래에 나누면 u.gg 패치 페이지가 되고 차별 문장이 죽는다.
   노트 행마다 관측 판정을 붙이고, **짝 없는 관측(미공지)을 같은 스트림에 삽입**해 accent 좌측 레일로 들어올린다.
   수용 기준: 상단 스크린샷만 보고 "패치노트 요약 사이트"로 오인되면 실패.
2. **상태 색은 게임이 바뀌어도 불변**이다. `--accent`=미공지 · `--danger`=공지-불일치 · `--warn`=표본 부족 · `--success`=상승.
   `[data-game]` 블록에서 상태 색을 재정의하지 말 것.
3. **근거 없는 문장은 회색(`--muted`)** — 전원 합의 설계 요건. LLM이 후보를 못 찾으면 "근거 없음"을 그대로 노출한다.
4. **Riot 로고·상표 사용 금지**(아래 §5).

## 2. 확정 팔레트 — V4 · 협곡 나이트(라이트 그라운드)

`docs/design/DESIGN-TOKENS.md`에 **먼저 추가**한 뒤 `src/styles/tokens.css`에서 참조한다(임의 값 추가 금지 규율).

```css
[data-palette="v4"], :root {          /* 기본값 = V4. 진입 시 항상 이 값 */
  --bg:#030d18; --surface:#0a1626; --surface-warm:#12213a;
  --border:#8c6b33;                    /* 골드 프레임 — V4의 정체성 */
  --border-soft:#242c3a;
  --fg:#f0e6d2; --fg-2:#c3b79f; --muted:#8b8677;
  --accent:#c8a355; --accent-on:#030d18;
  --success:#0ac8b9; --warn:#f59e0b; --danger:#cf4740;
  --game-wash:#0a1626; --game-glow:#c8a355;
}
```

**선정 경위**: 사용자가 V3(협곡 나이트)를 선호하되 "너무 어둡다"고 했고, 재보니 취향이 아니라 실측 결함이었다 —
V3의 `--muted`는 surface 대비 **3.52:1**로 WCAG AA 본문(4.5:1) 미달, 골드 보더 `#785a28`도 **2.85:1**로 비텍스트(3.0:1) 미달.
V4는 **골드 프레임은 유지하고 미달분만 상향**했다.

| 토큰 | surface 대비 | 기준 | |
|---|---|---|---|
| `--fg` | 14.67:1 | 4.5 | ✓ |
| `--fg-2` | 9.17:1 | 4.5 | ✓ |
| `--muted` | 5.00:1 | 4.5 | ✓ |
| `--accent` | 7.64:1 | 3.0 | ✓ |
| `--border` | 3.69:1 | 3.0 | ✓ |
| `--danger` | 4.00:1 | 3.0 | ✓ |

**남은 트레이드오프 1건**: 골드 accent(`#c8a355`, 색상각 40°)와 표본 부족 앰버(`#f59e0b`, 38°)는 색상각이 사실상 같고
채도만 다르다(52% vs 93%). 뱃지는 항상 라벨 텍스트를 달고 나오므로 색은 보조 단서다. **대조표에서 두 뱃지가
같이 뜨는 화면을 실제로 보고**, 구분이 부족하면 뱃지 형태(보더 두께·점 모양)로 보조 구분을 넣는다.

**LoL 브랜드 색 실측(2026-09-10, 재조사 금지)** — leagueoflegends.com/ko-kr 렌더 DOM 계측:
`#0a1428` 배경 **516회로 압도적 지배색** · 헥스텍 골드 `#c8aa6e` · 청록 `#00a0ba` · 라이트 `#f0e6d2`.

### 기각된 안 (되살리지 말 것)
- **V1 헥스텍 골드** / **V2 마법공학 청록** / **V3 협곡 나이트(원안)** — 시안에 비교용으로 남아 있으나 구현 대상 아님.
- 현행 `#38bdf8` — 하늘색이라 LoL로 읽히지 않는다는 사용자 판정.

## 3. 게임 테마 구조 (멀티게임 확장)

```css
/* 팔레트가 중립8 + 상태4 + 워시2를 정의 */
[data-palette="v4"] { ... }
/* 게임 스왑은 그 **뒤에** 선언하고 **중립 8개 + 워시만** 덮어쓴다.
   같은 특정도(0,1,0)라 소스 순서로 이긴다 → 상태 색은 팔레트 값이 살아남는다. */
[data-game="pubg"] {
  --bg:#0b0906; --surface:#1a150d; --surface-warm:#262017;
  --border:#3a2f20; --border-soft:#2a2218;
  --fg:#faf7f2; --fg-2:#ded3c2; --muted:#a2947e;
  --game-wash:#241a0e; --game-glow:#f2a900;
}
[data-game="pubg"] .art { display:none }   /* PUBG 아트 미연결 */
```

- **저장하지 않는다**(사용자 결정). 진입 시 항상 LoL. 다른 게임은 선택으로만 전환 → localStorage 불필요, **FOUC 문제도 자동 해소**.
- `[data-theme]`과 직교하므로 나중에 라이트 축을 붙여도 간섭 없다.
- ~~⚠️ PUBG 중립 램프는 **V4 확정 이전에 잡은 값**이다. 실제로 붙일 때 V4 기준으로 재도출할 것~~
  → **2026-09-17 연결 + 재도출 완료**. 재측정 결과 텍스트 3종(`--fg --fg-2 --muted`)은 전부 V4(LoL)
  기준선보다 대비가 높아 위 값 그대로 채택했고, **`--border`만 `#3a2f20` → `#8f6a22`로 바꿨다**:
  문서값은 V4가 `--border`를 "보이는 골드 레일"(`#8c6b33`, `--panel-rail-from`이 소비)로 승격시키기
  *전*의 어두운 갈색이라 그대로 쓰면 PUBG에서 패널 레일이 사라진다. PUBG 앰버 계열에서 V4와
  **같은 비텍스트 대비**(surface-warm 대비 3.27)를 내는 값으로 재도출했다.
  실측: fg 16.98 / fg-2 12.28 / muted 6.11 (본문 4.5:1 통과) · border 3.27 (비텍스트 3.0:1 통과).
- 선택자는 `[data-game="pubg"]`가 아니라 **`:root:has([data-game="pubg"])`** 다 — 라우트별 `<html>`
  속성은 Next 16에서 route group 다중 root layout을 요구해 `<html>`/`<body>`와 공용 Header가 복제된다.
  클라이언트 래퍼(`GameRoot.tsx`)가 본문 최상단에 속성을 달고 `:has()`로 변수를 루트까지 끌어올린다
  (래퍼에만 걸면 `body`의 배경이 LoL로 남아 iOS 오버스크롤에서 색이 어긋난다).
- `[data-game="pubg"] .art { display:none }`의 실제 대상은 `.art`(시안 클래스명, 구현에 없음)가 아니라
  **협곡 래스터를 쓰는 레이어 전부**다: `.ambient-wash`·`.ambient-camera`·`.ambient-reveal`
  (`src/styles/ambient.css` 말미). 남는 `.ambient-glow`는 `--game-glow`를 소비하므로 PUBG 앰버로
  자동 전환된다.
- 컴포넌트는 이미 전부 토큰 참조라 **컴포넌트 코드 수정 없이** 램프 추가만으로 전환된다.

## 4. 화면별 구현 항목

### 4-1. 홈 (`src/app/page.tsx`, `src/components/home/*`)
- **릴리즈노트 스트림 신설** — 챔피언 카드(아이콘 **56px**) → 스킬 행(스펠 아이콘 **40px**) → `스탯: A ⇒ B` → 우측에 관측 판정 뱃지.
  데이터는 `data/aggregated/notes/{patch}.json`의 `items[]`(entity·skill·stat·before·after·direction)를 `entity`로 groupBy.
- **미공지 삽입** — 같은 스트림에 `.rn.gap`(surface-warm 배경 + accent 좌측 레일)으로 끼워 넣고, 노트 부재를 명시("✕ 26.17 패치노트에 로크 항목 없음").
- **라인 필터 6종** — 인라인 SVG 글리프(전체/탑/정글/미드/바텀/서폿). DDragon에 라인 자산 없음.
- **라인별 미공지 분포 패널** — 사이드. 실집계: 탑22·정글25·미드17·바텀24·서폿19(라인 표기 107건) + 라인 무관 130건.
- **헤드라인 수치 표기 정정** — `35`는 **노트 엔티티 수**(`countRelevantNoteEntities`), `215`는 **노트 항목 수**(`meta.itemCount`).
  현행처럼 "35개"로만 쓰면 항목 수로 오독된다. `35 엔티티 / 215 항목`으로 분리.
- **히어로 앰비언트** — 챔피언 스플래시를 `opacity:.30 + blur(2px) + saturate(.75)`로 깔고 `--game-wash`→`--bg` 그라디언트로 페이드.

### 4-2. 대조표 (`src/app/compare/page.tsx`, `src/components/compare/*`)
- **아이콘 0개 → 투입**: 노트 사이드바 행에 챔피언 아이콘 40px, 델타 테이블 엔티티 열에 40px.
- **라인 행(바텀·미드 등)** 은 챔피언 자산이 없다 → 현재 `골` 텍스트 박스를 **라인 글리프 박스**로 교체.
- 엔티티 열 하위에 라인 태그(글리프 + "탑 · 승률").
- 정렬은 기존 `writeDeltas` 상태 우선순위(미공지 최우선) 유지.

### 4-3. 항목 상세 (`src/app/item/[id]/page.tsx`, `src/components/item/*`)
- **CI 오차 막대를 실제로 그린다.** 현재 범례가 "95% CI 오차 막대"를 약속해놓고 그리지 않는다.
  패치별 CI는 `data/aggregated/{patch}/champions.json`의 `ci.{pick,ban,win}`에 이미 있다(예: 로크 26.16 `[46.3, 48.2]`, 26.17 `[33.3, 35.2]`).
