# PLAN — 대조표 셀의 축 혼입 제거 (2026-09-20)

소스: 세션 대화(사용자 지시) · 파이프라인 `/sh-dev-loop --tdd --auto` → `/ship`

## 배경 (사용자가 스스로 진단한 원인)

> "이전에 분석내용애서 보이던 동일챔피언 다중행 현상을 슈정해달라요청햇엇는데, 이게 라인별 분석내용이
> 별건이라그런현상이 발생햇던거같아. 때문에 라인별변동률은 살리되 전체필터상태일때 구분이되도록하고싶은데
> 어떻게해야하는거지?"

델타 행의 id에 라인이 들어 있다 — `champion:MonkeyKing:winRate`(전체)와
`champion:MonkeyKing:JUNGLE:winRate`(정글)는 **모집단이 다른 별개 관측**이다. 라운드6에서 "엔티티
1행"으로 접으면서 지표당 한 칸만 남기도록 했고, 그 접는 규칙이 두 부작용을 냈다:

1. **전체 행이 이기면 라인 수치가 사라진다** — 26.17→26.18 실측 **16칸**.
2. **라인 행이 이기면 전체 수치처럼 보인다** — 축 표시가 작은 글리프 하나뿐이라
   "오공 승률 ▼10.8%p"(전체)와 "아트록스 승률 ▼10.0%p ㅜ탑"(탑 한정)이 같은 종류로 읽혔다.

아트록스가 이 결함의 대표 사례다:

```
TOP  승률 50.9% → 40.8%  Δ-10.1pp  n=287/316  q=0.069  ← 유의
all  승률 49.2% → 43.1%  Δ -6.1pp  n=376/376  q=0.280  ← 변화없음(정글 +4.8 등에 희석)
```

## 확정 요구사항 (사용자 원문)

> "오케이. 그러면 전체가 default, 유의미한 라인별지표가있을때만 추가로보여주는거로."
>
> "/sh-dev-loop --tdd --auto 이후 /ship 진행해"

- R1. 지표 셀은 **전체(scope=all) 관측을 1급**으로 둔다.
- R2. 그 지표의 **라인 한정 관측이 보고 가능(`isReportableRecord`)할 때만** 라인 관측을 함께 든다.
      (= "유의미한 라인별 지표가 있을 때만 추가로")
- R3. 전체가 보고 가능하지 않은데 라인만 있으면 **`전체 —`** 로 그 사실을 말한다.
- R4. 축 라벨(`전체` / 라인 글리프)은 **전체 필터에서 항상** 붙인다 — "표기 없으면 전체"라는
      암묵 규칙을 없앤다. 라인 필터가 걸려 있으면 뗀다(필터 칩이 이미 축을 말한다).
- R5. 배틀그라운드도 함께 볼 것(사용자: "리그오브레전드 뿐아니라 배틀그라운드도").

## 제외 합의 (검토 후 기각)

- **X1. 셀에 `+N라인 표본부족` 힌트** — 사용자가 먼저 제안했고("추가해주는게 좋긴할거같은데"),
  같은 메시지에서 스스로 규정·카운트 문제를 제기해("그렇게되면 표본부족으로 제거된 항목들에대한
  규정과 cnt도 다시생각을해야하지않나?") 검토 후 **기각**했다. 근거 4개:
  ① 라운드6 C1 결정과 충돌 — `ReleaseNoteRow.tsx:231`이 "사유 어휘는 노이즈"라고 이미 박아 뒀다.
  ② 분모가 3겹 — 오공 승률에서 안 보이는 라인 4개 중 TOP/MIDDLE/UTILITY는 표본부족이고
     BOTTOM은 **행 자체가 없다**(양쪽 0판). `+3`은 바텀을 숨기고 `+4`는 미출전을 표본부족이라 부른다.
  ③ 표본부족만 세는 건 자의적 — 라인 행 탈락 사유는 표본부족 532 · 바닥미달 142 · 변화없음 571.
  ④ 밴률은 라인 축이 없어(밴은 픽 전) `+N`이 영원히 안 붙는다 → "밴률은 표본 충분"으로 오독.
  추가로, 어느 헤드라인 카운트에도 안 들어가는 **집 없는 숫자**가 셀마다 흩어진다.
- **X2. 푸터 모수 고지(`판정 보류 1,772`)** — 대안으로 제시했으나 사용자가 채택하지 않았다.

## 확인된 사실 (재조사 금지)

- 집계는 **모든 챔피언**에게 `scope="all"` 1행 + 픽이 1판이라도 있는 라인마다 `scope="position"`
  행을 만든다(`aggregate/champions.ts`). 판정은 5라인을 전부 순회하고 **양쪽 0판인 라인만**
  건너뛴다(`match/delta.ts`). 26.17→26.18: 챔피언 173명 · 전체행 519 · 라인행 1312
  (5라인 52명 · 4라인 73명 · 3라인 23명 · 2라인 10명 · 1라인 15명).
- 화면 생존: 전체행 519→41 · 라인행 1312→18. 라인행이 더 걸러지는 건 표본이 쪼개져
  `insufficient-sample`이 41%(532/1312)이기 때문(전체행은 9%).
- 축 구조가 지표마다 다르다: **픽률** 전체 = 라인들의 **합**(분모가 총 매치 수로 동일) ·
  **승률** 전체 = 라인들의 **표본가중 평균** · **밴률** 라인 축 **없음**(`banRate: isAll ? … : null`).
  카밀 실측: 서포터 −2.94 + 탑 −1.14 + 정글 −0.11 = −4.19 = 전체 픽률 Δ.
- **PUBG는 이번 변경 대상이 아니다**(R5 확인 결과): 무기 델타는 47행 × 1지표(`pickupShare`)이고
  **세그먼트 축이 아예 없다**. 맵 델타(`map-deltas.json`)는 맵 자체의 지표 5행이고 `status`가 없다
  (판정이 붙지 않는다). 즉 "전체 vs 세그먼트"가 한 셀에서 경쟁하는 구조가 존재하지 않는다.
  다만 표본부족 은닉은 공통이다 — PUBG도 `isReportable(status)`로 2건(JS9·DP12)을 감춘다.
