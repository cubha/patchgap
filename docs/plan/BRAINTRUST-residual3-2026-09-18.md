## 2. B2 — 섹션 제목 4건을 "엔티티 카드"가 아니라 "섹션 묶음"으로

- **파서 수정(a) 기각 사유(렌즈 2·4 합의)**: `candidateSetHash`가 전체 노트 직렬화 해시(llm-match.ts:355, `section` 포함)라 노트 1건만 바뀌어도 그 패치쌍 **LLM 캐시 전량 무효** → Opus 최대 400건×2쌍 재호출. note id에 엔티티 슬러그가 들어가 `deltas` 재생성·커밋 산출물 변경. 26.19 CI(9/24) 직전에 감당할 비용이 아니다. 선택하려면 confirm 필수.
- **표시 층위(b) 채택**: 키 후보 실측 — `anchorKind==="section"`은 피오라 65건도 잡아 불가 · `entity ∈ sections[]`는 의회·증강·버그 수정을 못 잡아 불가 · `section ∈ {system, other}`는 의회(`champion`)를 못 잡아 불가. 성립하는 키는 **이미 page.tsx:64에서 계산되는 `resolveStreamEntityIcon → entityType null`** ∧ `!isCosmeticGroup` ∧ 짝 델타 0행. 26.18에서 정확히 4건, 26.17에선 `챔피언 변경`·`아트`·`시스템 사양 업데이트`도 걸리나 그것들도 실제 섹션 라벨이라 오탐 아님(테스트에 26.17 케이스 포함).
- **렌더 변경**: `ReleaseNoteRow` summary에 "섹션 묶음" 분기 — 첫 글자 아이콘 대신 섹션 라벨, 제목 톤 `text-fg-2`, 관측 줄 대신 "N개 항목 · 패치노트 섹션". `unpaired` 배지·34행·`skill===null` 비병합은 그대로(cosmetic-note.ts 결정 원문 ①②③ 보존 — 렌즈 1).
- **정렬**: `contentTier`에 섹션 묶음 티어를 추가(관측 없음 2 뒤 · 치장 3 앞). **다른 탭·층위로 옮기지 않는다** — 옮기면 `contentCount = meta.itemCount`와 화면 행 수가 어긋나 R3 "타일 49 vs 화면 47"이 재현된다(렌즈 2).
- **점수 실효**: rubric "파서 잔여물 0"은 프로덕션 실렌더 기준 — 렌더에서 엔티티 카드가 0이면 조건 충족. **조건부 +1**.
- **confirm**: (b)는 불필요. (a)는 채택하지 않는다.

## 3. E2 — 관측 없음 그룹의 접기

- **실효 있는 방식은 하나뿐(렌즈 3·4 합의)**: 카드는 이미 `<details>` 접힘이라 "카드 접기"·"높이 축소"는 실효 0. tier 2 그룹(8~13행, 6건)을 **요약 1행 `<details>`**("관측 변화 없음 · 6건 ▸", 펼치면 카드 그대로)로 묶어야 첫 10행이 관측 7 + 요약 1 + 섹션 묶음 2가 된다. rubric 문구 "같은 빈 문장의 **연속** 노출"이 정확히 이것을 잰다.
- **방어책(렌즈 2)**: ① 요약행에 **건수만** — 사유 문구를 쓰면 "대표 1행 사유 거짓"이 그룹 단위로 재발(6건 중 5건이 `mixed`라 단정할 사유가 없다) ② 요약행을 `entries`의 한 항목으로 두어 레인 필터 빈 상태(ReleaseNoteStream.tsx:157)와 충돌하지 않게 ③ 항상 접는다 — "tier 2가 5개 이상일 때만" 같은 조건 분기 금지(26.19에서 관측 그룹이 7 미만이어도 거짓이 없도록 건수 표기).
- **구현 제약(렌즈 4)**: `ReleaseNoteStream`은 `"use client"`라 tier를 page.tsx에서 계산해 prop으로 내린다. 카운트 배지(`headline.noteItemCount`)·`StreamLaneFilter`(라인 축)와 무관.
- **점수 실효**: **조건부** — 3/10=5점 척도가 자체 정의라 "연속 노출 0"이 측정 가능한 주장이어도 +1은 채점 해석. 접힌 묶음을 회색 잡음으로 볼 여지 있음.
- **confirm: 필요** — 스트림 원칙("한 스트림에 대조")의 변형이고, 점수 실효가 불확실한 채 UX 패턴을 바꾼다.

## 4. 렌즈 충돌·병합

- 렌즈 1이 지적: B2(섹션 묶음)와 E2(접기)가 **같은 건(의회 = no-pair)을 두 층에서 다르게** 다룰 위험. 병합안: E2 접기 대상은 **tier 2(관측 변화 없음)만**, 섹션 묶음은 자기 티어의 압축 행으로 따로 렌더, 치장 3은 그대로. 한 건이 두 처방을 동시에 받지 않는다.
- 렌즈 2 "`section ∈ {system, other}`로는 의회를 못 잡는다" vs 렌즈 3·4 "아이콘 해석 실패 키로 잡힌다" — 후자가 실측으로 우선(page.tsx:64 결과를 그대로 쓴다).

## 5. 만점 항목 재확인 후보 — D4 4/4 (렌즈 3, 실측)

rubric D4 문구는 "모델명 노출 없음"인데 상세 1,737페이지 중 226에 "모델 claude-opus-5 · 캐시 …" 캡션(CausesPanel.tsx `llmCaption`)이 있다. R1 채점은 "요약문만" 세어 합격 처리 — rubric과 채점이 서로 다르다. 한편 D1은 "LLM 역할이 화면에 명시"를 요구하고 B3는 원천 표기를 요구하므로 캡션 자체는 지워선 안 된다. 판정: D4의 의도는 *LLM 문장이 사용자용*(프롬프트 흔적·원값·raw id)이고 출처 캡션은 LLM 문장이 아니다. 다만 캡션의 `claude-opus-5`는 raw 모델 id다 — 사람이 읽는 이름("Claude Opus 5")으로 바꾸면 D1·B3(출처)과 D4(raw id 없음)를 동시에 만족한다. 점수는 바꾸지 않되 rubric 문구를 "요약문·캡션에 raw 모델 id 없음"으로 정밀화하고 그 근거를 채점표에 남긴다.
