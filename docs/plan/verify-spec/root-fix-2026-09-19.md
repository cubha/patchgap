# VERIFY-SPEC — 결정 7건 근본해결 + 추가 5건 (2026-09-19)

## 구현 결정

- **`section` 재분류 대신 `modeScope` 신설.** 노트 id가 `note:{patch}:{section}:{slug}:{내용해시}`라
  section을 바꾸면 id가 바뀌고, 커밋된 두 델타 파일의 `matchedNoteIds`가 전부 댕글링되며
  `candidateSetHash`(전체 노트 직렬화)가 달라져 LLM 캐시 388건이 무효가 된다. 새 필드는
  `toCandidateView`가 직렬화하지 않아 캐시·id가 모두 불변이다.
- **노트는 재파싱하지 않고 마이그레이션.** 라이엇이 26.18 페이지를 발행 후 수정해(저장본 180 →
  오늘자 162) 재파싱은 관측 시점 사실을 파괴한다. `scripts/run-migrate-notes.ts`가 필드만 덧붙이고,
  modeScope 외 변경이 감지되면 기록을 중단한다.
- **LLM 교정은 후보 풀이 아니라 검증 지점에서.** 풀을 거르면 candSetHash가 바뀌어 유료 전량
  재호출이 된다. `verifyCauses`/`verifySummaryCites`가 비-core 인용을 기각한다(회색 처리).
- **프롬프트 v4는 이번에 하지 않는다.** 문구만 바꾸고 `PROMPT_VERSION`을 안 올리면 캐시된 답이
  그것을 만들지 않은 프롬프트에 귀속되고, 올리면 캐시 전량 무효 + 채점된 문장이 비결정적으로
  교체된다. 기계적 절반(길이·완곡 종결 집계 → `meta.llm.prose`)만 넣어 다음 실행을 측정 가능하게 했다.
- **`display-normalize.ts` 존치(멱등 가드로 강등).** 재생성 후 입력은 0건이지만, 노트만 갱신되고
  델타가 옛 판정으로 남는 중간 상태가 실제로 가능하다(재매칭은 로컬 전용, Vercel은 커밋본을 읽는다).
- **죽은 앵커는 되살리지 않고 뗐다.** `#discord` 섹션 제거는 2026-09-14 사용자 지시였다.
- **PUBG 원천 블록은 지우지 않고 접었다.** "모든 판정문은 원천 링크를 가진다"가 불변식이라,
  자연어 문장을 위로 올리고 파일 경로·매치 id는 `<details>`로 내렸다.

## 테스트 정합성 — 명세 변경 보고 2건

1. `src/components/home/__tests__/render.test.tsx`의 DiscordPanel 케이스: "마지막 전송"·"디스코드로
   브리핑 보내기"를 고정하고 있었으나 **그 문구가 거짓이었다**(정적 사이트는 전송하지 못하고,
   값은 델타 파일 생성 시각이며, "공지"는 방송 대상이 아니다). 통과시키려 고친 것이 아니라 문구가
   틀려서 함께 갱신했다.
2. 픽스처 팩토리 다수: `PatchNoteItem`에 필수 필드가 생겨 `modeScope`를 추가했다. 모드 앵커를 쓰는
   픽스처는 앵커에서 파생시킨다(고정값 `"core"`를 두면 모드 케이스가 조용히 core로 테스트된다 —
   실제로 처음 일괄 추가했을 때 display-normalize 테스트 7건이 그 이유로 깨졌다).
